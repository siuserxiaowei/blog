# 赛事雷达深度研究综述（2026-07-30）

本轮把“继续搜更多赛事”拆成 30 个独立研究责任域，并以官方主办方、政府通知、正式赛事平台和规则页为优先证据。研究结果不是直接发布清单；候选需经过数据契约、来源、资格、截止日和奖励类型校验后才能上线。

## 结论

赛事并不少，原雷达的主要问题也不是单纯“条数不够”，而是四类机会混在一起：

1. 独立赛事与子赛题重复计数。
2. 比赛、Grant、加速器、榜单、征集和行业活动共用一个截止模型。
3. 报名截止、作品提交、开赛、决赛、报告截止被压成一个 `deadlineISO`。
4. 官方、政府、平台、媒体和聚合站未结构化区分。

现有 `172` 条更准确的口径是：约 `145` 个赛事系列、`172` 个赛题或机会记录。继续扩充前，必须先让页面能表达“是什么机会、谁能参加、下一步截止是什么、来源是否可靠”。

## 明确排除或降级的典型

- 已过 Entry Deadline、只剩旧参赛者提交阶段的 Kaggle 赛事。
- 标题把 Credits、会员、软件许可和多人份权益相加成巨额“奖池”的 Devpost 项目。
- 中国居民不可投，却仍被本站标成 S/A 级默认推荐的项目。
- 滚动加速器、Builder Program、投资计划和商店推广，不能当作现金比赛。
- 常设漏洞赏金、训练平台与普通行业会议，不能伪造截止日进入赛事池。
- 只剩线下决赛或推荐通道的项目，不能继续显示“公开报名”。
- 只有第三方聚合站、通用首页或登录墙，没有可行动报名入口的条目。

## 当前数据 P0

1. 多条记录把开赛、活动开始、报告截止或占位日期当成报名截止。
2. `oh` 与 `stepsoftware2026` 的主要 URL 已确认 404。
3. `creatorhackathonvol1` 把活动日期当成未核验的报名截止，且匿名入口落到登录页。

## 站长 ROI

不要同时开发十个参赛项目。最优策略是一个母产品、多种比赛包装：

> 教师工作台 / 个性化学习 Agent  
> 教师输入目标 → 学情诊断 → 任务规划 → 内容生成与审核 → 学生反馈 → 教师复盘

同一资产可包装为：

- GOAI：开源 Skill / MCP / 工作流
- 讯飞教育赛：真实教师验证与学习效果
- RevenueCat Shipaton：新的窄场景移动订阅产品
- CCF / OPC：一人公司的人效和商业案例
- CALL-E：家长或客户语音回访模块

资源建议：60% 投母产品与真实用户，20% 投开源资产，15% 投可复用 BP/案例，最多 5% 用于短期顺手投。

- “人工整理 · 最后核验于……”
