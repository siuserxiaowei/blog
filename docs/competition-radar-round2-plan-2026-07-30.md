# 赛事雷达第二轮：自主执行计划与 50 个检查点

更新时间：2026-07-30  
基线：184 条机会 / 赛题记录，183 个赛事系列；本轮合并后 202 条；线上 JSON schema 2.0。

## 执行契约

- 模式：Managed Execution，自治等级 L4。
- 目标：重新检索仍可报名或即将开放的软件、AI、Agent、算法、开源、游戏、创意与创业机会，同时复核旧数据并降低主雷达页面成本。
- 可直接执行：公开信息检索、本地读写、分支与 worktree、测试、构建、浏览器验收和用户已明确授权的生产部署。
- 委派：只并行互不依赖的三条线；新增数据、旧数据更正、前端性能文件所有权互斥。
- 主 Agent 责任：检查来源、审阅 diff、运行独立测试、决定是否合并、解决共享集成点、回收 worktree。
- 暂停条件：需要新凭证、付费、删除用户数据、修改无关系统或事实证据否定核心方向。
- 重试规则：同类失败最多进行 3 轮有证据的修复；不能用重复尝试代替诊断。

## 真实完成标准

1. 新增记录必须有官方或主办方一手来源，且不与现有 184 条重复。
2. 截止日期必须区分 confirmed、estimated、rolling、unknown；后三者不得进入紧急倒计时或 ICS。
3. 旧数据复核至少覆盖全部 urgent 和全部已标 verified / partially-verified 记录。
4. 主雷达仍保留搜索、筛选、排序、URL、收藏、空状态、ICS、移动端和无障碍能力。
5. 构建后的赛事首页目标小于 1.2 MB，DOM 元素目标小于 8,000。
6. 数据、链接安全、构建、桌面、移动端与生产环境均有可复核证据。
7. 子 Agent 报告、仅有计划、搜索摘要或未运行验证均不算完成。
