# siuser小伟：品牌与首页决策

> 本文是这次主页优化的决策底稿。它优先约束内容、信息架构和转化路径，再约束视觉与代码。

## 1. 网站要解决什么

这不是一个泛泛的个人作品集，也不只是文章、工具和项目的入口。

它的首要任务是让有真实重复流程的小团队负责人快速判断：**这里有人能把一段业务摩擦，拆成可运行、可复盘的 AI 系统。**

因此首页的行为路径是：

`识别自己的重复问题 → 看懂交付方法 → 查看公开证据 → 带着一条流程发起沟通`

文章、工具、项目和比赛雷达是信任证据与长期公开日志；它们不应该和业务系统交付抢夺首页的主叙事。

## 2. 核心主张

**让 AI 在业务里跑起来，而不只停在演示里。**

辅助说明：

> 我把重复沟通、流程转运和内容生产，拆成有人机分工、可上线、可复盘的业务工作流。

这句话统一以下能力，而不把它们散列成“我会很多 AI 工具”：

- 客户沟通系统：AI 语音机器人、外呼与回访。
- 流程协作系统：表格、消息、资料与状态流转的自动化。
- 内容与知识系统：选题、生产、分发、归档与复用。

轻量内部工具和数据看板是以上三条系统的承载层；除非它成为最强业务线，否则不在首页与三条主线并列。

## 3. 受众与筛选

主受众是已经有明确业务流程、且正在为人工重复操作付出成本的小团队负责人或业务负责人。

好的询盘应能带来至少一项材料：现有话术、表格、消息记录、流程描述或希望达成的业务指标。首页 CTA 应鼓励这种“带着一条流程来聊”的开始方式，而不是泛泛地说“合作咨询”。

不承诺没有授权或可核验依据的客户结果。未公开验证的材料统一称为“方案示例”“工作流拆解”或“运行单示意”。

## 4. 故事线与视觉锚点

### 故事线：从现场到系统

`观察现场摩擦 → 拆出最小闭环 → 上线并交接 → 用运行数据复盘`

它既解释了网站为什么存在，也决定了页面的阅读节奏：先看问题，再看方法，再看系统形态与证据，最后行动。

### 专属锚点：流程运行单

不复制其他个人站的角色 IP 或宇航员意象。本站采用可反复出现的“流程运行单”：一张像工作底稿的结构化表单，固定展示：

`场景 / 重复动作 / AI 接管 / 人工兜底 / 成功标准 / 当前状态`

首页中的运行单必须标明“示意”，避免将其伪装成真实客户案例。后续服务页、案例页、文章页和工具页可沿用这个结构，形成一致的视觉与内容记忆点。

## 5. 视觉执行规则

- 保留米白、墨黑、砖红的编辑部/工作底稿气质；不回退到深色霓虹、粒子和泛 AI 渐变。
- 用编号、状态章、流程线、批注和留白表现“运行中”，而不是无目的动效。
- 标题表现判断，正文优先可读。Mono 只用于状态、字段、编号和元信息。
- 动效只保留首屏进入、链接 hover、滚动显现；用户打开页面后应先读懂，后感到精致。

## 6. 首页信息架构

1. **首屏 / 定位与运行单**：一句主张、清楚的交付说明、主次 CTA，以及一张流程运行单示意。
2. **问题识别**：重复沟通、信息转运、内容再生产三类常见摩擦，帮助访客快速自我归类。
3. **方法**：业务诊断、最小闭环、上线交接、运行复盘，明确 AI 与人工的边界。
4. **三条系统路径**：客户沟通、流程协作、内容与知识，链接到对应交付说明。
5. **公开证据**：文章、工具、项目的作用是证明判断密度与持续实践，不是堆入口。
6. **行动**：引导访客带着一条真实流程联系，并告知应准备什么。

## 7. 不该做什么

- 不把“会 AI”“会 Agent”“60+ 工具”放到主张的位置。
- 不为营造科技感而加入无法解释的 3D、粒子或泛化 IP。
- 不把未经授权的流程称作客户案例或写出无法核验的效果数字。
- 不让内容、工具、项目、服务在首页拥有同等优先级。
